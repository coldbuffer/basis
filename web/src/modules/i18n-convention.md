# Module i18n convention (target)

Normative shape for `web/src/modules/<segment>/i18n/`. Aggregated access is `t.<namespace>.<area>.*` from `src/i18n/en.ts` / `zh.ts` (`core` and each module). Legacy `t.kb*` / `t.pages.*` / camelCase leaves are removed; bridges like `graphCopy()` may still accept camelCase keys at call sites.

## File layout

| Path | Role |
| --- | --- |
| `i18n/en.ts` | English message tree (`export default { … }`) |
| `i18n/zh.ts` | Same keys as `en.ts` |
| `i18n/index.ts` | Barrel: `default as en` / `default as zh` (run `refresh-module-i18n-index.mjs`) |

No other locale filenames under `i18n/` long term (no `kbReview.ts`, `pages-*.ts`, …). Bridges like `screen-copy.ts` stay only while non-React code cannot use `messagesForLocale`.

## Namespace = module directory name

- Segment folder name is the namespace: `review`, `graph`, `admin-audit`, …
- **Hyphens → underscores** in the namespace identifier (valid TS / `t` path): `admin-audit` → `admin_audit`, `entity-resolution` → `entity_resolution`.
- Locale files use **`export default { … } as const`** (no repeated namespace const — the segment folder is the namespace).

```ts
// modules/review/i18n/en.ts
export default {
  page: { … },
  menu: { … },
} as const;
```

Module barrel re-exports both locales:

```ts
// modules/review/i18n/index.ts (generated by refresh-module-i18n-index.mjs)
export { default as en } from './en.js';
export { default as zh } from './zh.js';
```

`i18n/en.ts` and `i18n/zh.ts` merge `core` and generated `i18n/module-locales.ts` (run `refresh-module-i18n-index.mjs` after adding a module).

React: `t.review.page.subtitle` (not `t.kbReview.*` after migration).

## Key path: `<namespace>.<area>.<snake_leaf>`

| Segment | Meaning | Examples |
| --- | --- | --- |
| `namespace` | Module id (`review`, `admin_audit`) | — |
| `area` | Screen or concern | `page`, `list`, `dialog`, `menu`, `chrome` |
| `snake_leaf` | **snake_case** string key | `open_decisions`, `col_time`, `empty_title` |

Logical path examples:

- `review.page.subtitle` — route page chrome
- `review.queue.approve_label` — widget section inside module
- `graph.menu.graph_diff` — nav label owned by graph module (alongside per-segment `*.menu.*` keys)
- `admin_audit.list.col_time` — admin list table

**snake_case** applies to **object keys** (leaves and intermediate groups if multi-word): `empty_graph_title`, not `emptyGraphTitle`.

Use `fmt(t.review.page.count, { count: n })` for interpolation; placeholder names in strings stay `{count}`, `{id}` (snake ok too if consistent).

## Areas (second segment)

Prefer a small fixed vocabulary:

| Area | Use for |
| --- | --- |
| `page` | `index.tsx` route shell: title, subtitle, crumbs helpers |
| `menu` | Sidebar / nav labels for this module |
| `list` / `detail` / `dialog` | Major screens under `pages/` or `components/` |
| `chrome` | Legacy area key; prefer module-owned copy |

Avoid a literal dot-string `"module.page.xxx"` as one key — use **nested objects** so TypeScript autocompletion and `audit:locale` keep working.

## Global / core

| Location | Namespace |
| --- | --- |
| `src/i18n/core/en.ts`, `zh.ts` | `common`, `api_error_codes`, `shell`, `workspace_nav`, `workspace_runtime`, `dev` |

Do not duplicate `common.*` inside modules.

## Graph canvas area

Explorer toolbar / dock strings live under `graph.canvas.*` (flat leaves next to `inspector`, `helpers`, `plugins`, …). React may use `t.graph.canvas.timeline_play`; TS bridges use `graphCopy(locale, 'timelinePlay')` with snake storage.

Sidebar nav labels live per module (`graph.menu.graph`, …); resolve via `workspaceNavMenuLabel(t, labelKey)` in `lib/workspace-nav-label.ts`.

## Tooling

| Script | Purpose |
| --- | --- |
| `scripts/audit-locale-usage.mjs` | Unused-key heuristic (`npm run audit:locale`) |
| `scripts/refresh-module-i18n-index.mjs` | Regenerate module locale barrels and `src/i18n/module-locales.ts` |
| `scripts/fix-i18n-snake-props.mjs` | Fix TS2551 camelCase property access on locale objects |

After adding a module, run `refresh-module-i18n-index.mjs` to refresh `module-locales.ts`.

**Checks:** `npm run audit:locale && npm run typecheck && npm test`
